# 变量管理

本指南详细说明如何在 KeyenceAgent 中管理 PLC 变量，包括全局变量、局部变量、变量规划和最佳实践。

## 变量基础

### KEYENCE 变量类型

| 类型 | 地址范围 | 用途 | 示例 |
|------|----------|------|------|
| **位设备** | R0~R99999 | 内部继电器 | R0, R100 |
| **位设备** | B0~B99999 | 链接继电器 | B0, B100 |
| **位设备** | MR0~MR99999 | 保持继电器 | MR0, MR100 |
| **位设备** | LR0~LR99999 | 锁存继电器 | LR0, LR100 |
| **位设备** | CR0~CR99999 | 控制继电器 | CR0, CR100 |
| **位设备** | T0~T2047 | 定时器触点 | T0, T100 |
| **位设备** | C0~C2047 | 计数器触点 | C0, C100 |
| **位设备** | DM0.00~DM65535.15 | DM 位 | DM100.00 |
| **字设备** | DM0~DM65535 | 数据存储器 | DM100, DM200 |
| **字设备** | EM0~EM65535 | 扩展存储器 | EM100 |
| **字设备** | FM0~FM32767 | 文件存储器 | FM100 |
| **字设备** | W0~W9999 | 链接寄存器 | W100 |
| **字设备** | TM0~TM2047 | 定时器当前值 | TM0 |
| **字设备** | CM0~CM2047 | 计数器当前值 | CM0 |

### 全局变量 vs 局部变量

**全局变量：**
- 所有程序模块可访问
- 地址在整个项目中唯一
- 用于模块间数据共享

**局部变量：**
- 只在定义的模块内可见
- 不同模块可使用相同的局部变量名
- 用于模块内部临时计算

**KEYENCE 的特殊性：**
KEYENCE PLC 的变量是地址导向的，不像 IEC 61131-3 那样有严格的变量声明。KeyenceAgent 通过变量表（TSV）来管理变量的语义化命名。

## 变量操作示例

### 基本读写

```
创建变量读写示例项目：

1. 读取输入：
   - 读取 DM100（输入字节），拆分到 R100~R107

2. 写入输出：
   - 合并 R200~R207 到 DM200（输出字节）

3. 模拟量处理：
   - 读取 DM300（温度，范围 0~1000）
   - 转换为摄氏度（0~100°C）
   - 存储到 DM400
```

**程序逻辑示例：**
```
; 读取输入字节并拆分
MOV DM100, DM700      ; 临时存储
LD DM700.00
OUT R100
LD DM700.01
OUT R101
...

; 合并位到输出字节
LD R200
OUT DM750.00
LD R201
OUT DM750.01
...
MOV DM750, DM200

; 模拟量转换
; DM300: 0~1000 → DM400: 0~100
MUL DM300, 100, DM401   ; DM401 = DM300 * 100
DIV DM401, 1000, DM400  ; DM400 = DM401 / 1000
```

### 数组操作

```
创建数组操作示例：

1. 数组赋值：
   - 将 DM300~DM307（8个元素）全部设为 0

2. 数组拷贝：
   - 将 DM300~DM307 拷贝到 DM400~DM407

3. 数组求和：
   - 计算 DM300~DM307 的总和，存储到 DM500

4. 查找最大值：
   - 找出 DM300~DM307 中的最大值，存储到 DM510
```

**程序逻辑示例：**
```
; 数组赋值为 0
MOV 0, DM300
MOV 0, DM301
...
MOV 0, DM307

; 数组拷贝
MOV DM300, DM400
MOV DM301, DM401
...

; 数组求和（使用循环或展开）
MOV 0, DM500          ; 初始化总和
ADD DM500, DM300, DM500
ADD DM500, DM301, DM500
...
ADD DM500, DM307, DM500

; 查找最大值
MOV DM300, DM510      ; 初始化为第一个元素
LD DM301
> DM510
JMPN SKIP1
MOV DM301, DM510
SKIP1:
; 继续比较其他元素...
```

### 间接寻址

```
创建间接寻址示例：

功能：
- 使用 DM0 作为索引
- 访问 DM100~DM107 数组
- 读取 DM100[DM0] 的值到 DM200

示例：
- 当 DM0 = 0 时，DM200 = DM100
- 当 DM0 = 3 时，DM200 = DM103
```

**程序逻辑：**
```
; 计算目标地址
ADD 100, DM0, DM1     ; DM1 = 100 + DM0

; 间接读取
; 注意：KEYENCE 的间接寻址语法可能因型号而异
; 需要查询具体指令手册
```

AI 会根据 KV STUDIO 版本自动选择合适的间接寻址指令。

## 变量命名规范

### 推荐的命名风格

**1. 语义化命名**
```
✅ 好的命名：
- TemperatureSensor1
- EmergencyStop
- ValveOpenCommand
- ProductCounter

❌ 不好的命名：
- Temp1
- ES
- V1
- Cnt
```

**2. 前缀规范**
```
前缀        含义              示例
────────────────────────────────────
btn_       按钮输入           btn_Start, btn_Stop
sens_      传感器            sens_Temperature
act_       执行器            act_ValveOpen
sts_       状态标志          sts_Running
cmd_       命令              cmd_Reset
err_       错误标志          err_Timeout
```

**3. 数组和结构**
```
传感器数组：TempSensors[8]
控制字：SystemControl_Word
位字段：SystemStatus_Running (对应位)
```

### 创建命名规范文档

```
生成变量命名规范文档 NAMING_CONVENTION.md：

包含：
1. 命名风格（驼峰/下划线）
2. 前缀规范
3. 类型后缀（如果需要）
4. 禁用词列表
5. 示例

将文档添加到项目 references/ 目录。
```

```

1. 重复使用的地址
2. 地址分配建议
3. 可用地址范围

生成冲突报告 VARIABLE_CONFLICTS.md。
```

**AI 会自动检测并报告：**
```
⚠️ 地址冲突检测报告

冲突 1:
- DM100 被定义为 InputByte1 (INT)
- DM100 也被定义为 TempSensor0 (INT)
建议：将 TempSensor0 移到 DM300

冲突 2:
- R0 被定义为 SystemRunning (BIT)
- R0 也被功能块实例 1 内部使用
建议：功能块使用 R1000+ 地址

可用地址：
- DM300~DM499（200 个字）
- R100~R999（900 个位）
```

### 自动修复冲突

```
自动修复变量地址冲突：

1. 保持系统关键变量地址不变（R0~R99, DM0~DM99）
2. 重新分配冲突的变量地址
3. 更新 variables.tsv
4. 更新 MNM 中的地址引用
5. 生成变更报告
```

## 变量验证

### 地址合法性检查

AI 会自动检查：
- ✅ 地址范围是否合法
- ✅ 数据类型是否匹配
- ✅ 位设备是否用于字操作
- ✅ 字设备是否用于位操作

**示例错误：**
```
❌ DM100.16: 位地址超出范围（应为 0~15）
❌ R0: 尝试作为 INT 使用（应为 BIT）
❌ DM100000: 地址超出范围（最大 65535）
```

```
生成报告 VARIABLE_USAGE.md。
```

**示例报告：**

## 最佳实践

### 1. 预留地址空间

```
为每个功能模块预留足够的地址空间：

工位 1: DM1000~DM1099（100个字）
工位 2: DM1100~DM1199
工位 3: DM1200~DM1299

即使当前只用了 20 个字，也预留完整的 100 个字。
这样扩展时不会与其他模块冲突。
```

### 2. 使用符号名而非地址

在 MNM 中尽量使用符号名：

```
✅ 好的做法：
LD TemperatureSensor1
> HighTempThreshold
OUT HighTempAlarm

❌ 不好的做法：
LD DM300
> DM310
OUT R10
```

AI 生成代码时会优先使用符号名。

### 3. 文档化变量

```
为每个变量添加详细注释：

DM300, INT, "温度传感器1 - 范围0~1000，对应0~100°C，单位0.1°C"
DM500, INT, "阀门开度 - 范围0~1000，对应0~100%"
R0, BIT, "系统运行标志 - 1=运行，0=停止"
```

### 4. 分组和对齐

```
将相关变量分组并对齐：

; 温度传感器（连续地址）
DM300, INT, "温度传感器1"
DM301, INT, "温度传感器2"
DM302, INT, "温度传感器3"
DM303, INT, "温度传感器4"

; 压力传感器（连续地址）
DM310, INT, "压力传感器1"
DM311, INT, "压力传感器2"
```

### 5. 避免魔法数字

```
定义常量而不是硬编码：

定义常量：
- HIGH_TEMP_THRESHOLD = 800
- LOW_TEMP_THRESHOLD = 200
- MAX_VALVE_OUTPUT = 1000

在程序中使用常量名。
```

AI 可以在生成代码时自动处理常量替换。

## 常见问题

### 问题 1：变量粘贴失败

**症状：**
```
KV_VARIABLE_PASTE_NOT_PERSISTED
变量表未成功写入项目
```

**原因：**
- TSV 格式不正确
- 包含非法字符
- 列数不匹配

**解决：**
AI 会自动修复 TSV 格式并重试。

### 问题 2：地址越界

**症状：**
```
编译错误：设备地址超出范围
```

**解决：**
```
检查并修正超出范围的地址：
- DM0~DM65535
- R0~R99999
- T0~T2047
- C0~C2047
```

### 问题 3：类型不匹配

**症状：**
```
编译警告：位设备用于字操作
```

**解决：**
```
修正数据类型：
- 位操作使用 R, B, MR, LR
- 字操作使用 DM, EM, FM, W
```
