为什么电气工程师需要这个项目

KV STUDIO 是一款面向人设计的 PLC 开发工具，工程师通过鼠标点击完成所有操作。这对人来说很直观，但对 AI Agent 来说是一堵墙：项目的关键信息散落在 UI 的各个角落，没有任何 API 可以读写。

🗂️

信息极度分散

全局变量、功能块接口、程序体、EtherCAT 配置、扩展单元分散在 UI 的五个不同区域，AI 无法获取项目全貌。

📖

专有指令未被 AI 训练

基恩士有大量私有指令（Z.RSTB、MC_MoveAbsolute 等专有用法），通用 IEC 61131-3 知识不够用。

🖱️

只有 UI，没有 API

KV STUDIO 没有脚本 API，所有操作都必须模拟鼠标键盘，且需要处理各种弹窗和确认对话框。

整体架构

KeyenceAgent 把三个困难分别交给三个技能解决，形成一条从查询 → 编程 → 写入 → 验证的完整流水线。

三个技能详解

📚

技能 1 — 知识库技能

kv-studio-kb-programming

在编写任何基恩士特有代码之前，必须先查询本地 Wiki V2 知识库。通用 IEC 61131-3 知识明确禁止作为基恩士专有语法的唯一来源。

  • 查询本地 SQLite 数据库（wiki.v2.cleaned.db）
  • 按来源分类：htmlhelp（指令语法）、table（设备映射）、dockinghelp（运动参数）、pdf（手册）
  • 输出 chunk ID 和 source anchor，确保可溯源
  • 弱召回时有恢复策略（retrieval-playbook）
⚙️

技能 2 — 编程技能

keyence-plc-programmer

生成 KV STUDIO 可导入的 MNM 格式程序资产。不直接触碰桌面，所有写入操作由操作技能完成。

  • ST / 梯形图程序体
  • 变量声明（全局/局部）
  • 功能块接口设计
  • 用户数据类型（结构体）
  • MNM 编码：普通程序 CP936；KV-X520 域 ST 用 UTF-16LE BOM
  • 包含 FB 设备泄漏检查（导入前预验证）
🖥️

技能 3 — 操作技能

kv-studio-operator

直接操作 KV STUDIO Windows 桌面应用。所有 UI 操作通过命名工作流统一入口，每步产出可验证的证据文件。

  • 仅接受 manifest 中 customer_callable: true 的工作流
  • 全部 UI 原子操作通过 kv_ui_guard.ps1 防护层执行
  • 机器级互斥锁，防止并发 UI 冲突
  • 每步输出：run.log、step receipt JSON、结果 JSON
  • 支持平面执行计划（flat execution plan）模式

操作技能的内部分层

端到端工作流

以下是一个完整的例子：工程师描述任务，Agent 全程自动完成。

任务示例： "给 KV-X310 新建项目，创建一个功能块，判断轴当前位置是否在目标范围内，输出 BOOL 信号"
1

查指令语法

知识库技能查询 MC_MoveAbsolute、位置比较相关的基恩士专有用法与设备地址

2

生成程序资产

编程技能生成 ST 程序体 MNM，以及分开的 FB 自变量、局部变量和全局变量 TSV

3

创建项目 & 导入

操作技能创建项目，导入 MNM，写入 FB 自变量和局部变量，再设置全局变量；需要调用时创建实例并绑定实参

4

编译 & 验证

执行编译，读回结果 JSON 确认 ok:true，生成项目快照供工程师查阅

项目快照：让 AI 看到全局

调用 export_kv_project_text_snapshot 工作流，可以将 KV STUDIO 项目中散落各处的信息统一导出为结构化的语义快照，供 AI 读取、分析、或作为下一轮编程的上下文。

restore_plan.json 给出依赖顺序的恢复序列，entities.jsonl 是机器可读的实体索引。快照里的 semantic_project_status 字段是完整性的权威指示器。

Harness 执行链

每次调用工作流，都经过一条严格的执行链：Agent 只能触达最顶层的 customer_callable 入口，内部各层的逻辑对外完全不可见。

调用工作流的完整命令格式

# 导入 MNM 程序模块
powershell -STA -NoProfile -ExecutionPolicy Bypass -File \
  kv-studio-operator\scripts\workflows\import_kv_module.ps1 \
  -ProjectPath "C:\KvAgentWork\MyProject" \
  -MnmPath    "C:\KvAgentWork\output\main_program.mnm"

# 写入 FB 自变量（IN / OUT / IN-OUT）
powershell -STA -NoProfile -ExecutionPolicy Bypass -File \
  kv-studio-operator\scripts\workflows\set_kv_fb_arguments.ps1 \
  -ProjectPath  "C:\KvAgentWork\MyProject" \
  -FbModuleName "FB_PositionCheck" \
  -ArgumentsTsv "C:\KvAgentWork\output\arguments.tsv"

# 写入局部变量和全局变量
powershell -STA -NoProfile -ExecutionPolicy Bypass -File \
  kv-studio-operator\scripts\workflows\set_kv_variables.ps1 \
  -ProjectPath        "C:\KvAgentWork\MyProject" \
  -LocalProgramName   "FB_PositionCheck" \
  -LocalVariablesTsv  "C:\KvAgentWork\output\locals.tsv" \
  -GlobalVariablesTsv "C:\KvAgentWork\output\global_vars.tsv"

# 导出语义项目快照（只读，不修改项目）
powershell -STA -NoProfile -ExecutionPolicy Bypass -File \
  kv-studio-operator\scripts\workflows\export_kv_project_text_snapshot.ps1 \
  -ProjectPath    "C:\KvAgentWork\MyProject" \
  -SnapshotOutput "C:\KvAgentWork\snapshot"

查询所有可用工作流及其参数，运行能力查询脚本：

powershell -NoProfile -File \
  kv-studio-operator\scripts\get_kv_capabilities.ps1

安装

# 克隆项目
git clone https://github.com/LiangYH/KeyenceAgent.git
cd KeyenceAgent

# 一键安装与状态检查
powershell -ExecutionPolicy Bypass -File setup_keyence_agent.ps1

配置文件

在 %APPDATA%\Codex\kv-studio-operator\ 下创建 config.json（参考 kv-studio-operator/config/kv-studio-operator.example.json）：

{
  "kvs_exe": "C:\\Program Files\\KEYENCE\\KV STUDIO\\Kvs.exe",
  "work_root": "C:\\KvAgentWork",
  "admin_credential_path": "%APPDATA%\\Codex\\kv-studio-operator\\credentials.xml",
  "admin_user_default": "Administrator",
  "wiki_root": "D:\\KeyenceWiki"
}

调用工作流的方式

所有工作流统一用以下方式调用（由 Agent 执行，不需要工程师手动输入）：

powershell -STA -NoProfile -ExecutionPolicy Bypass -File `
  kv-studio-operator\scripts\workflows\import_kv_module.ps1 `
  -ProjectPath "C:\KvAgentWork\MyProject" `
  -MnmPath "C:\KvAgentWork\output\main_program.mnm"
提示： 查询当前可用的工作流和参数说明，运行 get_kv_capabilities.ps1，它会读取 script_manifest.json 并返回所有已发布工作流的参数列表。
