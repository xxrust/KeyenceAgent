# KEYENCE KV 基础与反直觉清单（读代码 / 改工程之前先读）

本文只放两类内容：**大模型最容易按其它品牌习惯搞错的地方**，以及**本仓库实测踩过的坑**。
每条都标了依据类型：

- 【手册】= 本机 KEYENCE Wiki（`kv-studio-kb-programming` 检索到的帮助/手册条目）
- 【实测】= 在这台机器上用 KV STUDIO 12G 或真实工程验证过
- 【仓库】= 本仓库的约定（不是 KEYENCE 规定）

> 用法：读一个陌生 KEYENCE 工程、或准备改程序/变量/注释之前，先扫一遍本文；遇到本文没覆盖的
> KEYENCE 专有语义，再走 `kv-studio-kb-programming` 查证，不要凭通用 PLC 记忆回答。

## 1. I/O 与软元件：**没有 X/Y**

| 反直觉点 | 正确的做法 |
|---|---|
| 直觉上"输入是 X、输出是 Y"（三菱/欧姆龙习惯） | 基恩士 KV 的**单元 I/O 落在 R（继电器）区**：R 区低段是**输入继电器**、再一段是**输出继电器**。 |
| 想找硬接线点就 `grep "LD X"` / `"OUT Y"` | 找不到是正常的，别据此判定"这台机没有 IO"。要看 **EtherNet/IP 单元 / 扩展单元的 R 区分配**。 |

- 【手册】FUN `RefreshX（输入继电器状态刷新）` 的参数就是 `InRelay`（输入继电器起始）与
  `OutRelay`（输出继电器起始），位点数 1～256 —— 说明 I/O 是按 **R** 表示的。
- 【实测】本机 KV-X310 工程把全软元件导出（`PlcDeviceValue.csv`，882,542 行）后，出现的区段只有
  `R / MR / LR / B / W / DM / EM / FM / CM / T / C / CR / ZF`（外加 `B0B`、`W0F4` 这类十六进制写法），
  **没有任何 X 或 Y 区段**。
- 【实测】台州检测机这台机的现场 I/O 就是 EtherNet/IP 单元的 `R30000` 起（输入 0/1/4/10）与
  `R30100` 起（输出 0–4/11/14）；轴的信号走 EtherCAT（`_MC_Axis[1..3]`），不在 R 区。
- 结论：判断"有多少现场点"时，先看单元配置里单元的**分配首地址**，再看 R 区里实际被程序引用到哪几位。

## 2. 三套"命名/注释"机制，别混为一谈

| 机制 | 存在哪 | 程序里显示成什么 | 批量导入/导出 |
|---|---|---|---|
| **软元件注释**（device comment） | 工程里的注释库 `<项目>.cm1` | 设备仍是 `MR1`，**旁边挂注释** | 文件菜单 CSV/TXT 往返 |
| **变量**（设备绑定变量） | 变量表 | 显示**变量名**（如 `轴2同步解除允许`） | 变量表 TSV 粘贴 |
| **变量注释** | 变量表的 comment 列 | 变量表/编辑里显示 | 同变量表 |

- 三者**互不替代**：写 `.cm1` 不会让程序里出现变量名；建变量也不会自动有注释。
- 选哪一套见主技能里的「变量表 vs 软元件注释」策略；一句话：**新项目默认变量表；老项目按现状**。
- 【实测】注释表往返：`文件(F) → 读取 CSV/TXT 格式的软元件注释(Q)` 可以写回 `.cm1`，
  导入后必须导出回读逐条 diff 才算验收（导入框那句「读取了 N 个」只是旁证）。

## 3. MNM 程序体（导出/导入的文本格式）

| 反直觉点 | 正确理解 |
|---|---|
| `BOX_ST` 后面以 `;` 开头的行像是被注释掉的代码 | **是 ST 代码**。`;` 是 MNM 的 ST 行标记，不是注释符。 |
| 以为 MNM 能当源码直接读 | 它是**助记符列表**，可导入导出，但不是结构化源码；`;MODULE_TYPE:0` 是普通程序、`:2` 是用户 FB。 |
| 按 token 位置硬推 FB 参数映射 | 实参是位置化的，**个数常常少于签名参数**，中间参数可能用 `???` 占位。要映射必须用 FB 签名 + KV STUDIO 的自变量表核对。 |
| 以为 `???` 是坏数据 | 是导出器对"未指定实参"的表示，**原样回导可编译**。 |
| 定时器号随便用 | **同一 `TMR`/`TMH`/`TMS`/`TMU` 编号出现在两个模块**会报 `[错误61]`。 |

- 【手册】`TMR` 是 **100ms 32 位减定时器**，参数写作 `TMR ([EN], Timer, In100ms)`，即设定值单位是 100ms：
  `TMR T5 #20` = 20 × 100ms = **2.0 s**。`#` 前缀表示常数。
- 【实测】库 FB `MC_MultiParameterRead_PANAS_A6BE_V100` 的 `BOX_ST` 之下直接就是
  `;FOR Idx := 0 TO MAX_PARAMETER_NUM BY 1 DO` —— 厂家自己也是这么写的，可以确认 `;` 是代码。
- MNM 编码：**UTF-16LE + 带 BOM**；`DEVICE:` 码按 CPU 系列不同（KV-X310 = `59`，KV-X520 = `60`），
  含中文的 MNM 必须用目标编码写。

## 4. 数据类型与宽度（上位机/变量表都受影响）

- 后缀：`.L` = 32 位整数（2 字）、`.F` = REAL（2 字）、`.DF` = LREAL（**4 字**）。
- 【实测】工程里常见 `x1000` 整数缩放：PLC 内部浮点工艺值 ×1000 → 整数给上位机。
- 设备名会被**归一化**：`MR0001 → MR001`、`DM0001 → DM1`；`B`/`W` 是十六进制（`B0B`、`W0F4`）。
  做导入/比对前先做 key 归一，否则会出现"导入了但 diff 对不上"。

## 5. 工程文件：`.kpr` 不能离线解析

- 【实测】`<项目>.kpr` 头 8 字节是 `PROJECT` + 版本 2，正文是压缩/加密二进制 → **不能用文本工具读**。
- 程序体在 `All.prgx`、注释库在 `<项目>.cm1`（`COMMENT` + 版本 2 二进制），同样是私有格式。
- 所以顺序永远是：**在 KV STUDIO 里导出（MNM / 注释 CSV / 变量表 / 结构体）→ 再分析**，不要试图反解 `.kpr`。
- 工程目录里那些监控器残留（`PlcDeviceValue.csv`、`KvsMon.ini`、`MonEnv.kmu`、`sample.al2`、
  `UnitSet.ue2.old`、`LbkMdm.iniLbkMdm.ini`）**不是工程内容**，别当配置读。

## 6. KV STUDIO 桌面自动化的反直觉点（12G 实测）

| 现象 | 处理方式 |
|---|---|
| 文件名输入框 `GetDlgItem(1148)` 拿到的是 `ComboBoxEx32` 容器，`WM_SETTEXT` 无效 | 用 `EnumChildWindows` 找内层 `Edit` 再写 |
| 写进去了但 `WM_GETTEXT` 读回空串 | 跨进程读只能走 **UIA**（`ClassName=Edit` + `AutomationId=1148` 的 `Current.Name`） |
| 信息框找不到按钮（`GetDlgItem(IDOK)` 为空） | 它是 **DirectUI** 窗口：UIA 里所有元素都是 `ControlType.Pane`，没有 Button。做法是**文本白名单 + Enter**（`AllowTargetClose`），绝不盲点 |
| 枚举 `#32770` 时多出一个 `InterpreterC` | 那是**不可见常驻窗口**，必须用 `IsWindowVisible` 过滤，否则每次运行都"看起来残留弹窗" |
| 上一次轮询没有弹窗、下一拍才出现 | 沉降条件要"**连续 3 s 无弹窗**"，不是"这一拍无弹窗" |
| 想用 UIA 的 `Invoke` 点菜单项 | 这类菜单项 `Invoke` 会**阻塞到模态框关闭**；菜单用受保护的 `Alt+F` 加速键，UIA 只用来抓证据 |

## 7. 写脚本的硬约束（仓库级，违反会被门禁拦）

- 【仓库】`.ps1` 里**含非 ASCII 就必须 UTF-8 带 BOM**。否则 Windows PowerShell 5.1 按 ANSI(GBK) 读，
  中文路径字面量（如 `'配置\EtherCAT'`）会变成乱码目录名——实测在快照产物里出现过
  `閰嶇疆` 与 `配置` 并存的目录分裂。`script-hygiene` 门禁会拦这一类。
- 【仓库】`.bat` 必须**纯 ASCII**（cmd 会把中文参数变成 `?`）。
- 【仓库】Windows PowerShell 5.1 的坑：`@($list)` 放进**哈希表字面量**会抛
  `Argument types do not match`，用 `$list.ToArray()`。
- 【仓库】不要临时拼键盘/鼠标；所有 UI 输入走 `scripts/guards/kv_ui_guard.ps1` 的受保护动作。

## 8. 开工顺序（一句话版）

查 KB → 在 KV STUDIO 里导出/快照 → 判断这个工程是"裸地址+注释"还是"已变量化" → 选对注释/变量策略 →
改 → 编译 + 回读验证 → 报告。
