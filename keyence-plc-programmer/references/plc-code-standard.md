# KEYENCE PLC 代码规范

适用于整机新建、重构和跨模块逻辑。以项目本体中的设备、工艺、对外接口和目标 CPU 为输入。局部改动沿受影响的接口使用相应条款。 [项目本体与行为验证](project-model.md)

## PLC 扫描与状态所有权

**工艺上，多路控制可以同时处于活动状态。** 轴可以运动，工站可以等待到位，停止与故障条件依然需要周期检查。用保持的步号和许可表达等待，用完成反馈或超时推进步骤。脚本也占用扫描时间，等待外部动作应跨扫描，用动作状态和定时器表达。这里的同时活动描述设备状态，不表示每条梯形图语句都在独立线程运行。

**执行上，CPU 周期性地按模块和指令顺序求值。** `MOV`、`RES` 等指令每次遇到成立的执行条件都会写入。只应在特定事件写入时，使用对应的首扫、边沿、步转换或请求受理条件。除跳转、中断和宏等控制外，同一扫描内排在写入后的回路可读到已更新的普通内部软元件，排在前面的回路要等下次扫描。普通 I/O 通常在主程序结束后批量刷新，内部结果的可见时点与物理端子更新时点分别核对。直接 I/O 刷新、高速功能、中断及通信或单元数据更新按目标机型、配置和读写位置查证。每个输出指定一个最终写入者，多个条件汇总到该处。依据为 `KvsHardNanoC.pdf` p205「模块执行顺序」及指令参考 `END/ENDH`、`RFSX/RFSY`、`OUT/OUB`、`INT/RETI`。 [基恩士手册入口](https://www.keyence.com.cn/support/user/controls/plc/manual/)

| 信号用途 | 组织方式 |
| --- | --- |
| 持续条件或组合许可 | 到使用处按当前条件求值。需要复用时在一处驱动命名信号，使成立和撤销路径都可读。 |
| 命令、复位、参数装载 | 在首扫、请求受理、模式切换、步转换或复位事件写一次。请求一旦消费，在所属位置清除或应答。PLC 可写的外部参数只由约定的写入者在指定时机更新。多项纯数据初始化可用同一首扫条件下的框脚本表达。 |
| 步序和扫描临时值 | 步号在满足转移条件时提交。每步都读同一个尚未提交的当前步时，可在末尾提交下一步来避免连跳。只有存在可说明的取样一致性或读写先后需要时才设步号副本。扫描临时量在求值范围内初始化，并明确在哪些回路读取。仅本模块读取的状态优先用无设备地址的局部标号。 |
| 每次扫描无条件传送 | `CR2002 + MOV` 每次执行到该行都会写目标。保留有实际读者的连续映射、需固定时点的采样或临时量准备。固定值优先放在设定或初始化时点，命令值由受理事件写入。检查同一扫描中间值是否被读取，以及持续写入是否覆盖 PC、别的模块或中断的更新。把多行 `MOV` 合并成脚本时，仍需逐项判断哪些写入确实需要每次扫描发生。 |

用按扫描边界推进的对照验证连续转移、多个请求同时到达、停止与完成同时成立，以及相关的中断或外部更新。只有需要维持可见的握手、步骤、诊断或统计时才引入计数。每个计数写清**谁读取、据此做什么、何时加一、何时清零**，跨接口时还要定义位宽及回绕。只服务于测试断言的计数放在测试工具中。有调试用途的输出计数留在约定的观测点，写明计数对象和口径。 [基恩士指令参考手册，MOV](https://www.keyence.com.cn/support/user/controls/plc/manual/) · Wiki `InstructionRef--KVSREF-FC24CM_041J-MOV`

## 模块职责与归属

| 职责 | 模块负责的工作 | KV-X 样例依据 |
| --- | --- | --- |
| I/O 映射 | 输入侧把端子、网络点及有效电平映射为设备或工站信号。输出侧把命名的输出请求映射到硬件。每个物理输出指定一个最终写入者。轴定位硬件接管的接口归轴控制。 | `IO输入 [1]`、`IO输出 [18]` |
| 初始化与设备模式 | 根据上电、模式切换和复位条件初始化声明和状态。设备模式管理整机运行许可、自动、手动、暂停和故障恢复，并按需协调各工站。 | `初始化 [4]`、`设备状态 [15]`、设备模式 FB `FB_McMode` |
| 执行器控制 | 每个执行器有一处命令仲裁和执行入口。同一根轴的启动、原点复归、停止以及会影响本笔运动的参数写入，由明确的轴控制路径负责。对调用方返回动作状态及错误原因。 | `调用轴控FB [7]` 绑定 `_MC_Axis[i]` 与 `gAxis[i].Ctrl/Param/Status`，把运动处理交给 `FB_Motion` |
| 工站工艺 | 工站拥有自身步序、超时和外设释放条件。每步写清等待条件、发出的动作和推进条件，通过执行器接口发请求与收结果。 | `ST00_插针_演示 [8]` 的 `1010` 发相对定位，`1015` 等该动作完成后推进 |
| HMI／PC 接口 | 有对端的设备由此处解释外部地址、请求及参数，在相应模式下提交内部命令，并发布经过定义的状态。每个地址的读写方、数据类型、允许写入时机和应答语义可查。 | `HMI [17]` 在手动模式把 `gHmiAxis` 的命令与参数映射到内部 `gAxis`，再回送轴状态；另有工站单步接口 |
| 报警与版本 | 执行器或工站判断本地故障，报警模块汇总与发布，设备模式依据报警类别决定停机与恢复。为整机交付记录程序版本、接口版本和行为变更，关联对应源码或工程版本。 | `Alarm报警 [16]` 声明报警分类；`版本管理 [24]` 是后备模块，样例只有变更记录标题 |

模块通过命名信号交互。明确谁提出请求、谁确认接收、谁写动作状态、谁清请求或结果。允许多个命令来源时，在执行前按模式和仲裁规则合并。标出普通停止、设备故障与现场安全许可的来源及作用。小工程可在同一模块用书签和相邻回路保留边界，大工程按工站或职责拆扫描模块。模块数量随可读性和共享资源调整。

样例使用的名称和顺序用于查证。知识库证据为 `x:snap:overview`、`x:snap:prog:HMI`、`x:snap:prog:调用轴控FB`、`x:snap:prog:ST00_插针_演示`、`x:snap:fb:FB_Motion`、`x:snap:prog:Alarm报警`、`x:snap:prog:版本管理`。版本记录可放在不参与常规扫描的工程位置或项目发布记录。只有对端要求运行时版本时，才定义 PLC 发布字段。样例的演示轴模块也绑定了相同系统轴，复用范例时须查所有调用和运行许可。 [KV-X 样例工程树](../../kv-studio-operator/references/KVX样例程序_v100/WsTreeEnv.xml)

整机交付且用户要求参照 KV-X 工程架构时，先确认目标 CPU 支持的程序树类别，并把样例职责映射到实际工程树。工程内的版本履历写明版本、日期和变更，可仿照样例放在仅用于记录的后备模块。保存重开后回读程序树、扫描顺序、版本履历、各模块的梯形图行注释和标号绑定，同时验证软元件注释。目录、行注释、软元件注释、标号分别使用对应的工程回读证据。标号使 MNM 显示名变化时，按实际标号表还原地址比较指令。

## 接口、步骤和扫描顺序

1. **列出命令对照。** 按外部地址或内部请求逐项记录触发条件、允许模式、实际动作与顺序、参数及单位、受理或拒绝的结果、最终结果和复位方。重构时对照旧接口及本次需求。凡涉及已有命令动作、动作次序或对端语义变化，必须有对应的需求或约定。单个数值参数变更也需查其消费者及更新时间。
2. **区分命令和实际结果。** 一次动作依次判断参数及许可、受理、执行、成功或异常。已有状态足以证明本笔归属时可复用，否则用动作来源、序号或等效握手消除旧完成和迟到响应。就绪、执行中、完成、停止、故障分别给出成立条件。多字参数按协议约定完成提交和取样。往返等组合工艺明确整周期的参数取样和资源占用规则。

   审查执行器时，逐阶段列出受理及完成所依据的反馈、竞争事件的优先级、错误码和清理条件。同一条设备错误可以在启动、运行、停止阶段出现。按实际阶段匹配处理逻辑，避免用步号大小推断「是否需要监视错误」。例如发出减速停止后，分别验证停稳、停止期间设备报错及停止超时，并保持已承诺的清理动作。对脚本输出也写清何时更新，参数拒绝时旧值能否继续使用。安装宏 `PLS-H20G`、`APSET1-H20G`、`ORG2-L40` 和 `APRF` 提供这些接口设计的案例。 [安装示例索引](../../kb-pipeline/kvs-install-examples.md)
3. **写清状态转换。** 每步能从代码直接读出进入、等待、成功退出及故障、超时、取消时的清理。保留可诊断的故障来源和错误码。绝对零距离定位、允许零动作与要求实际位移的工艺分别定义判据。涉及相机或外设时，明确触发、输出反馈和对端结果。约定使用触发计数时写清计数事件和读者。
4. **按运行顺序推演。** 在模块表写清每次扫描、首次扫描、中断、后备模块启动与停止的次序。为每个跨模块变量记录唯一写入者、读取者和可见时点；存在多个请求源时单独定义受理与冲突结果。说明动作是否能在同一扫描推进。KV-X 样例轴控排在工站和 HMI 前，轴控在下一次扫描才读取工站写入的命令。工艺要求先撤销输出再发动作时，按实际 I/O 刷新或对端反馈定义生效条件，并按扫描记录状态变化。
5. **把工程写成可读的代码。** 模块名、书签和信号名采用项目统一用语。状态号、报警码、定时值和缩放比例应能追到名称、单位与定义。将同一条状态转换的判定和清理放在易追踪的位置。软元件注释说明信号或参数的用途，回路注释说明组合判据、扫描时序和工艺原因。生成源码时同样审查最终可读的 PLC 代码。

## 步骤号与手自动控制

顺序工艺用命名的当前步号选择执行回路。Nano 梯形图可用字寄存器和 `LD= DMxxx #10` 一类比较接点，先按步发请求，再凭本笔结果提出下一步。线性编号且每次事件只需推进一次时可用 `INC`。有分支、回环或预留步号时写入明确的目标步号，例如 `10 → 20 → 30`。

| 模式 | 推进规则 |
| --- | --- |
| 自动连续 | 本步动作完成且运行许可成立时，提交下一步。 |
| 自动单步 | 本步完成后保持当前步和待推进状态，收到有效的单步触发才提交下一步。约定提前触发是否丢弃，并防止按钮保持或通讯重复触发多步。 |
| 手动点动 | 正反点动从手动入口提交给执行器，受模式、方向互斥和运行许可约束。点动、松开按钮和手动动作完成均不写自动步号。切回自动时按工艺约定续跑、回等待位或重新初始化。 |

要求一次扫描最多推进一步时，各步骤回路使用同一当前步，提出待提交的下一步，由工站末尾的一处回路提交。验收时让下一步的条件预先成立，确认一次扫描只推进一步。另检查单步按钮长按、手动点动、切换模式以及停止或故障后待推进状态的处理。KV-X 样例的 `uNowStep/uNextStep` 与 `bCmdStep/bTrigStep` 见知识库 `x:snap:fb:FB_McMode` 和 `x:snap:prog:HMI`。Nano 例程在比较器中断内使用步号比较及 `INC`。 [Nano 变速例程](nano-official-samples/source/KVN14_Pos_CN.txt#L314)

## 扩展梯形图

目标机型支持时，梯形图默认采用扩展梯形图。每条回路围绕一个可独立理解的动作组织。同一条件下紧邻的指令可通过连接或分支共用接点。用助记符编写时，按基恩士指令语义使用 `CON` 连接输出指令后的逻辑。 [基恩士《KV STUDIO 使用手册》p154「扩展梯形图模式」及指令参考 `CON`](https://www.keyence.com.cn/support/user/controls/plc/manual/)

定时器专用于本步转移，且定时和转步原本相邻、使用同一步号时，将步号比较、定时和到时转步写在同一回路。

```text
LD= DM1342 #80
TMS #27 #10
CON
AND T27
MOV #90 定拍步号
```

`TMS` 由第 80 步使能，到时接点 `T27` 只约束后续的 `MOV`。合并前核对指令顺序、同一扫描中的读写、定时器复位和原有联锁。存在独立的执行条件、不同的读写时点，或合并会使回路难以追踪时，按动作边界分行。验收已有程序的整理时，回读梯形图和助记符，核对连接条件及转步时机。

| 设计要素 | KV-X | KV Nano |

| 轴执行和诊断 | 查目标 CPU、运动单元和驱动器的 `MC_*` 指令／FB、轴引用、状态和诊断能力。 | CPU 内置脉冲轴按目标型号的原生定位指令、点参数和 `CR/CM` 编写梯形图。先查本轴占用、启动与停止条件，再核对错误位、错误码、执行点号与动作完成。信号归属必须能区分使用同一点号的不同请求。实际机械反馈以本机硬件与接口为准。 |
| 复用与语言 | 有明确职责时用用户 FB 表达实例化的组件。模板与库的能力须按型号和版本核实。 | 按目标 CPU 选择梯形图、KV 脚本和宏。采用宏前确认宏类型、调用时序、局部软元件及可用指令。将 KV-X 的 ST/FBD、`_MC_Axis`、PLCopen 运动 FB、结构体及实例数组按 Nano 的可用功能实现。用户明确指定语言的部分遵循约定。 |

Nano 的语法、模块生命周期、CPU 和软件版本差异以目标手册和同系列范例为依据。资源核对包括模块容量、局部与全局地址、双字重叠、定时器和中断分配。轴完成位、CPU 脉冲坐标与机械实际到位必须按各自反馈解释。 [Nano 编程摘要](nano-programming.md) · [Nano 官方定位范例](nano-official-samples/source/KVN14_Pos_CN.txt) · [FB 重构判定](fb-first-refactor.md)

## Nano 工程组织与源码风格

### 工程职责与标号

沿用 KV-X 的职责划分，在 Nano 的原生程序树中按实际扫描顺序安排输入采样、设备管理、PC 接口、执行器、工站、报警和输出。版本履历放在后备模块。输入模块负责端子映射和输入边沿，工站决定信号如何推进工艺。高速配置和中断归属按目标 CPU 核对，移动回路前追踪信号在同一次扫描中的读写时点。

从项目接口、KV-X 模板和目标 CPU 手册选用英文标号。Nano 的全局标号可用 `对象_字段`，局部标号可省略模块已明确的对象名。工站步序沿用 KV-X 的 `NowStep`、`NextStep` 和 `ReadyForNext`，单步按模式选择 `StepMode` 和推进触发 `TrigStep` 表达。KV-X 中 `u`、`b` 分别是模板的类型前缀，Nano 按工程既有规则使用。见知识库卡片 `x:snap:prog:HMI`、`x:snap:fb:FB_McMode`。

工站、相机等顺序流程用 `Step` 表示步骤编号。执行器内部等待启动、运行、减速停止等控制阶段可用 `SequenceState`。硬件返回的控制状态保留手册的字段名，例如 KV-X 的 `PosCtrlState`。需要在模块入口取值时，可用局部 `StepAtEntry` 或 `StateAtEntry`，并在注释中说明取值和生效时点。

运动标号、驱动器 I/O 和协议字段沿用已有英文名称。KV-X 的 `FB_Motion` 使用 `bServoReady`、`bPosBusy`、`bPosDone`、`bAxisError`，并从 `Axis.StatusBit.DrvAlarm` 取得驱动器状态。运动 FB 的 `Done`、`Busy`、`CommandAborted`、`Error` 为 BOOL，`ErrorID` 为诊断代码。驱动器实际提供 `INP`、`Ready` 或 `Alarm` 时，按其手册和 I/O 映射记录来源、极性和成立条件。用 PLC 定位完成信号或软件组合判据得到的完成状态应按来源命名，例如 `PosDone`。见知识库卡片 `x:snap:fb:FB_Motion`、`fb:MC_MoveAbsolute`。

协议用一个字编码成功、停止和错误时，可用项目字段名 `ResultCode`，并列明值和有效时点。区分命令受理码、动作结果码和硬件 `ErrorID`。局部停止原因可用 `StopReason`，在说明里记录它何时锁存及返回。位置和速度标号优先保留项目采用的英文词汇，如 `TargetPos`、`StartVelocity`。单位写 `PLS`、`PLS/s` 或机械工程单位，引用 CM 表时可并列手册的 Hz。统一用「扫描」描述执行时序，核对双字占用和标号作用域。 [Nano 定位例程](nano-official-samples/source/KVN14_Pos_CN.txt#L438)

只在一个模块使用的状态和计算量优先声明为局部标号，由 KV STUDIO 分配存储，软元件或常数栏留空。跨模块交接、物理 I/O、PC 协议和硬件指令的固定地址按接口管理。迁移裸地址前检查脚本、间接寻址、批量初始化和掉电保持，保存重开后同时核对局部标号类型与实际引用。

工站和执行器负责本地故障判定及动作清理。报警模块汇总已确认的故障来源，按项目约定提供活动报警、原因及复位结果。忙、请求冲突和参数拒绝按命令结果处理。复位前检查故障源是否消失，报警发布与停机联锁分别按设备需求设计。

### 模块命名

Nano 程序树在原生类别下以扁平模块组织。自建模块用 `职责前缀_模块名` 表达分组，例如 `SYS_Init`、`PC_Commands`、`EXEC_Axis`、`ST_Inspection`、`IO_Outputs`、`DOC_VersionHistory`。先沿用项目已有的统一前缀，缺省时按工程职责定义一组，模块表列出前缀含义、原生类别和执行顺序。改名时检查模块启动或停止引用、调用、书签及联调引用，保存重开后回读工程树和实际扫描顺序。

### 梯形图与 KV 脚本

- 工站步序、手自动、单步、点动、联锁及实际 I/O 映射通常放在梯形图，人能在线追踪条件、定时和动作许可。
- 数值换算、按命令选择和校验参数、成组读写、批量初始化和命令结果分发优先使用 KV 脚本。用一个有明确入口、执行时点和结果的脚本表达一次完整的数据处理。已有长串传送或重复判据也按这条原则审查。有关运动的脚本写明操作数类型、单位及错误退出，梯形图可直接跟踪启动许可、运动指令和定时。
- 移植已有计算时，核对有符号、双字地址、浮点运算中间精度、舍入或截断、上下界及结果写入时机。条件执行可选框脚本，每次扫描执行可选域脚本。用目标 CPU 转换及回读确认实际语义，按项目用例验证正常值、边界、错误和扫描顺序。

### 官方例程注释

- 模块头沿用官方例程的分隔线、`File`、`Definition` 和 `Id` 布局。`File` 与工程模块名一致，`Definition` 写入口、关键参数和结果及必要单位，`Id` 写版本与日期。有明确维护单位时可填写 `Company`。正文使用项目语言。
- 用分节标题标出初始化、请求判定、动作执行、完成和异常退出等实际存在的段落。把组合判据、允许范围、跨扫描依赖及误用后果写在对应回路或脚本旁。官方定位例程在插补调用后单独开节说明须同时检查主轴和从轴完成。
- 长受理条件按工艺空闲、执行器许可和命令条件组织。在相关回路上方说明受理或拒绝的业务含义，重复条件需要复用时核对各读取点的扫描时序。顺序动作优先沿梯形图从左到右表达，适合同时发布的结果可共用分支。定时和到时动作由同一步负责时优先连接成一条回路。
- 一笔命令的交接和受理结果由同一次判定驱动。写入请求字、清除请求位或更新步号之后，复用原来的判定结果，或按同一回路的执行顺序组织写入。验收必须同时核对请求和结果，覆盖写入会改变判据的情形。
- 多个调用方使用同一执行器时，各方提交各自的请求，由执行器统一受理并记住本笔来源。记录应答何时有效，尤其是同一来源重复发相同命令时。验证忙时拒绝另一笔请求只影响该笔应答，正在执行的命令、参数和动作结果仍关联原调用方。
- 按工程编辑器实际显示验收版式，回读正文和所属回路。助记符导出里的分号与 `<h1/>` 属于源格式，写入时使用目标机型相应的行注释或标题功能。软元件注释仍按地址说明用途，标号说明名称以外的握手条件与单位。 [JOG 与直线插补例程](nano-official-samples/source/KVN14_Pos_CN.txt#L21) · [Nano 样例索引](nano-official-samples/README.md)

## 写入前审查

先在离线文件中完成模块表、接口对照、关键状态转换、源码和声明。可以复用现有项目文档。复杂项目至少从每条外部命令出发，沿实际扫描顺序追到物理输出和结果，逐项核对源码与需求。确认所有机械动作的入口、参数与反馈均能追到对应回路。

按影响范围检查同一扫描的请求竞争、忙时重发、旧完成或迟到应答、停机与定时到点同时成立、动作未启动或超时、零行程、故障清理以及下一笔请求。新写整机程序也要核对现有对端命令的实际动作。完成离线审查后再进入 KV STUDIO 作转换、回读和适用的运行验证。 [行为验证](project-model.md)
