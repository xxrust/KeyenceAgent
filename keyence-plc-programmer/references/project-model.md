# 项目本体与行为验证

项目本体记录现场器件、控制接口和程序状态之间的关系。它随目标工程版本和本次范围建立，可以是一份简明审查记录，也可以复用已有受控图纸、点表和时序表。整机设计、重写或全面审核覆盖下列各层。局部修改沿受影响信号追到生产者、消费者和外部接口即可。独立语法和算法示例沿用快速 ST 路径。

项目本体、现场参数、审查结论和验收回执归入该工程的任务目录。

## 建立基线与证据

记录工程路径、版本或快照指纹、CPU 和相关单元型号。既有工程从当前基线提取程序、声明、扫描顺序和配置。新设备从需求、电气图、I/O 表和外部接口资料建立设计基线。已有证据能对应本次版本和范围时可以直接复用。

每条支撑修改的关系标明出处和定位，例如图号及页码、端子号、PLC 模块及回路、PC 源码或协议字段、手册章节及适用型号、用户确认或联调记录。区分已证实、推断、未知和互相冲突的资料。源代码和配置可证实控制器的实现，图纸与现场记录可核实接线，接口规范和上位机实现可核实外部读写。标号、历史注释和样例用于定位线索。

## 按关系理解设备

| 从哪里查起 | 记录与变更有关的内容 |
| --- | --- |
| 电气与 I/O | 器件、端子或总线映射 → PLC 地址及配置 → 程序读写位置。记录方向、常态、有效电平、失电状态、单位与范围。分清物理点、逻辑标号、系统软元件和设备内部信号。检查地址别名、字宽重叠和间接访问。 |
| 设备目的与工艺 | 工位目标、手动／自动／调试模式、动作顺序和完成判据。把启动、暂停、停止、故障、复位、首扫和断电恢复写进相关状态转换。保留有依据的工艺顺序与时序。 |
| PLC 执行与资源 | 追踪任务、中断、模块扫描顺序和跨扫描状态。逐条查请求产生、接受或拒绝、执行、完成、异常退出及清理。记录同一执行器、输出或参数的多个写入者、优先级和访问时序。区分指令已执行、设备接受命令、动作实际完成和业务完成。 |
| HMI、PC 与外设 | 确认通信路径、地址／字段、数据类型、读写方、工件或请求归属、握手和清零时机。按接口需要核对忙时重发、拒绝、断线、重连与旧数据处理。直接接线的外设信号也要追到实际接收设备。 |
| 安全功能 | 追踪危险与安全功能、检测器件、安全继电器或安全控制器、最终执行元件及失电状态。明确安全回路怎样停止设备、如何复位、怎样防止意外重启，以及普通 PLC 映射中哪些位用于诊断或运行许可。确认安全功能须有回路和验证证据。 |

引用适用版本和条款。ISO 12100 用于危险识别与风险评估，IEC 60204-1 用于机械电气设备审查，安全相关控制系统按项目适用的 ISO 13849 或 IEC 62061 查证。按项目所在地、合同和设备类别确认采用版本及对应标准。基恩士手册及 Wiki 用于 CPU、单元、软元件和时序语义。厂商样例和仓库房规可用于实现参考。标准给出设计和验证依据，项目资料与实测支持对现场实现的判断。 [ISO 12100](https://www.iso.org/standard/51528.html) · [IEC 60204-1](https://webstore.iec.ch/en/publication/26037) · [ISO 13849-1](https://www.iso.org/standard/73481.html) · [IEC 62061](https://webstore.iec.ch/en/publication/59927)

## 从模型形成修改方案

每项行为修改先记录 **工艺要求 → 关联的信号、回路和外部接口 → 当前行为 → 目标行为 → 验收输入和预期结果**。证据有缺失或冲突时，写明待核事实、影响路径和所需资料，继续能独立确认的分析和改动。对未知互锁、外部写入或安全条件，保留受影响的原有逻辑，直到有证据支持替换。涉及官方实现与 FB 提炼时，依据目标 CPU、单元和行为要求评估。 [FB 重构判定](fb-first-refactor.md)

## 验证实际交付版本

将编译、保存重开和作用范围内的源码、声明、配置回读与最终工程版本对应。另存或继续修改后，核对最终交付副本的导出或指纹，复用仍能对应到最终内容且覆盖相同依赖的证据。验收记录列出适用的自动检查、仿真和现场检查及各自的执行状态。

行为用例按工艺与状态转换选取，运动和采集重点查请求被拒绝、完成反馈缺失、超时、零距离、同扫竞争、故障或停止后恢复。跨模块逻辑至少用实际模块及其扫描顺序做静态追踪或联测。模拟轴固定返回完成时，该用例只覆盖收到完成信号的路径。接线、物理动作、外部通信和安全功能按各自的现场证据报告。
