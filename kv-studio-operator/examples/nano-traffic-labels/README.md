# Nano 交通灯中文标号示例

从空项目建立交通灯程序，14 个实际使用的业务地址使用中文标号。3 个系统 CR 地址保留原地址和系统注释，不登记标号。全局标号保留地址绑定，框脚本、域脚本及梯形图的业务变量均使用标号；声明见 [labels.tsv](labels.tsv)，正文见 [phase.txt](phase.txt)、[area.txt](area.txt)、[ladder.txt](ladder.txt)。

| 原地址 | 中文标号 | 含义 |
|---|---|---|
| MR100 | 南北绿灯请求 | 南北方向处于绿灯阶段；输出还需通过东西方向互锁 |
| MR101 | 南北黄灯请求 | 南北方向处于黄灯阶段 |
| MR102 | 东西绿灯请求 | 东西方向处于绿灯阶段；输出还需通过南北方向互锁 |
| MR103 | 东西黄灯请求 | 东西方向处于黄灯阶段 |
| MR010 | 秒时钟上次状态 | 保存上一扫描的秒时钟电平，供脚本检测上升沿 |
| DM0 | 周期秒计数 | 28 秒周期中的位置，范围 0～27 |
| DM1 | 全红阶段记录 | 原程序的记录值：启动写 0，第一段全红写 2，第二段全红写 5；其他阶段不刷新，因此不是当前阶段连续状态码 |

| R502 | 南北绿灯输出 | 南北绿灯输出 |

| R504 | 东西黄灯输出 | 东西黄灯输出 |
| R505 | 东西绿灯输出 | 东西绿灯输出 |

| CR2008 | 保留系统地址 | CPU 运行开始时的首次扫描 ON |

南北/东西是本示例对两组灯的命名。保留原逻辑：0～9 秒南北绿灯，10～12 秒南北黄灯，13 秒全红，14～23 秒东西绿灯，24～26 秒东西黄灯，27 秒全红；启动将周期秒计数置为 27。物理接线仍由输出地址决定。

标号优先。四个阶段请求和六个灯输出的注释列为空；其余四行仅补充上升沿用途、计数范围、阶段记录不连续刷新及诊断值等信息。此示例的局部标号表保持为空，所有命名均为绑定原地址的全局标号。

禁止为有系统注释的软元件登记标号，禁止修改或清空系统注释。接口在 UI 输入前拒绝 CR/CM 整区的标号及设备注释写入；其他由目标 CPU 文档或工程证据确认的系统点也必须在规划时排除。禁止用尝试粘贴的方法探测系统地址。

手册依据：`pdf::KVSUSE_KVS11::chunk-078`（全局标号、位/整数类型及 Nano 名称长度）、`pdf::ScriptUse::chunk-029#p2`（脚本使用全局标号）、`pdf::KvsPtcPtoNano::chunk-001#p2`（CR2002/CR2006/CR2008）。输入接口接受 ASCII 标识符及常用汉字，按半角 1、汉字 2 检查 Nano 的 32 半角宽度限制；这不是对全部 Unicode 名称的支持承诺。

运行 [run.bat](run.bat)，默认创建 KV-NC32 空工程。所有 TSV、框脚本、域脚本、梯形图及回读预期先复制到本次输出目录的 `inputs/`，生成完整 `program.json`，然后交给公开 `nano_program_plan` workflow。flat executor 冻结契约与文件 SHA256，14 行标号一次粘贴，再写程序、编译、保存重开、核对整表、两段源码和七条梯形图，最后关闭测试进程。回读不符即失败。

```bat
run.bat -NoPause -OutRoot C:\kvrun\nano_traffic_new
```

`OutRoot` 必须是新目录。可用 `-SourceProjectPath` 和 `-ExpectedLabelsPath` 验证旧中文交通灯工程的副本；该模式只适用于本示例已验证的源码和回路布局，原工程按 SHA256 检查不变。直接公开 workflow 支持 `PlanOnly`，只生成计划；本 BAT 的 `PlanOnly` 仅预览空工程创建，不能代替完整程序验证。KV-X 不使用此路线。

KV STUDIO 覆盖粘贴会忽略空单元格。若目标空列需要清掉旧内容，接口先比对完整旧表并确认全部是用户标号，再清除整块四列表格、一次粘贴完整目标表并回读；不会逐格补空。旧表含系统点时拒绝整表重建。
