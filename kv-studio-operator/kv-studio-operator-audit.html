1. 审计范围

本文档描述 H:\KeyenceAgent\kv-studio-operator 当前代码的完整运行方式。 依据是 scripts/script_manifest.json、实际目录结构、flat executor、UI guard 和已产生的运行证据。

2. 总体架构

Agent 不拼接键盘、窗口或剪贴板操作。Workflow 只编排输入和步骤；Runner child 负责具体 UI 路线； 所有进程级输入必须经过 Guard。

2.1 script_manifest.json：运行时授权表，不是说明文件

manifest 的根字段是 schema_version、layout_policy、 customer_entry_policy、ui_atomic_actions、 step_result_contracts 和 classes。 它同时定义"谁可以被 Agent 调用""内部脚本能被谁调用""每步必须产生哪些结果文件"。

字段 源码含义 执行器如何使用
customer_entry_policy.
allowed_classes		 允许客户态入口的类：customer_workflow、harness、scaffold tool、non-UI tool、gate resolver 拒绝 internal class 被直接当作 Agent API
classes.
customer_workflow		 workflow 路径、published/pending 状态、customer_callable、runner children、capabilities 能力查询与 workflow 入口选择
classes.
runner_child_approved		 允许被 workflow 调度的 UI 子脚本 flat executor 仅接受 allowed classes
ui_atomic_actions.
approved		 Guard 中允许出现的全局输入函数名 静态 gate 发现未分类 action 即失败
step_result_contracts 每个脚本必须写的 JSON/artifact，支持 switch variant Get-KvStepContract 绑定本步骤验收文件

示例：runner_children/set_variables_guarded.ps1 默认必须写 set_variables_result.json 与 variable_persistence_validation.json； 带 -SnapshotOnly 则必须写 variable_snapshot_result.json。

4. Workflow 生命周期

阶段 系统动作 输出/停止条件
参数预检 检查项目、MNM、TSV、JSON 路径和必填参数 失败则不启动 UI
生成执行计划 列出顺序步骤、runner、输出目录、结果契约 execution_plan.json
静态门禁 检查 Guard 使用、approved action、Agent 边界 失败则不进入 KV STUDIO
互斥锁 取得 Local\KeyenceAgent.KvStudio.UI 占用时返回 KV_UI_WORKFLOW_BUSY
串行执行 按 plan 顺序调用 runner child，禁止并行 UI 操作 任一步失败立即停止后续步骤
结果验收 检查结果 JSON、receipt hash、当前运行日志和语义快照 不以文件存在代替成功

4.1 Flat Executor：执行计划的唯一 UI 调度器

源码：scripts/workflow_tools/invoke_kv_flat_execution_plan.ps1。 它不是业务操作脚本；它是计划解释器和可靠性边界。Workflow 只写 plan，Executor 才依次启动 gate、workflow tool 或 runner child。

源码步骤 具体行为 工程意义
读取 plan 要求 plan.ok=true、run_root、唯一 step.name、唯一 out_dir 拒绝模糊或复用输出目录的执行
解析 manifest 只允许 runner_child_approved、workflow_tool、gate 等类 禁止 workflow 任意执行路径
取得 mutex WaitOne(0) 获取 Local\KeyenceAgent.KvStudio.UI 不同 agent/process 不能并发操作同一桌面
指纹 写 code_fingerprint.json、输入 SHA-256 证据可追溯到当前代码与当前输入
Invoke-FlatWorkflowStep 启动单步，写 step_started / step_succeeded / step_failed 失败短路，禁止后续 UI 动作
最终验收 按 contract 读取结果；需要编译时还校验当前 run 的 OK/NG 文本 阻止旧文件或假阳性结果

5. UI Guard 原子动作

前台与窗口

Assert-KvUiForegroundHwnd Invoke-KvUiGuardForceForeground

输入前绑定目标 HWND/PID；最多一次受控前台恢复；失败不发送输入。

键盘与快捷键

Invoke-KvGuardedSendKeys Invoke-KvGuardedCtrlChord Invoke-KvGuardedAltVk Invoke-KvGuardedVkTap Invoke-KvGuardedShiftTab

记录 before/after，单个动作预算小于 10 秒。

剪贴板与输入

Invoke-KvGuardedClipboardPaste Invoke-KvGuardedClipboardSetText

剪贴板设置、Ctrl+V、目标焦点和结果写入同一 run.log。

鼠标与菜单

Invoke-KvGuardedMouseClick Invoke-KvGuardedMouseRightClick Invoke-KvGuardedMouseClickAllowProcessSuccessor

用于树节点和菜单，禁止无目的深层遍历。

模态关闭

Invoke-KvGuardedSendKeysAllowTargetClose Invoke-KvGuardedSendKeysAllowTargetCloseToWindow

用于已定义的弹窗关闭和后继窗口转移。

5.2 设计审查要点

  • 发布状态不等于真实验证通过：必须查看同次 run.log、receipt 和语义结果。
  • 静态门禁只证明调用边界，不能证明焦点、粘贴、变量或程序体正确。
  • UIA 找到窗口不等于控件获得焦点；Guard 只保护前台，业务 runner 仍需证明表格状态。
  • 所有 workflow 必须 flat；客户 workflow 不应递归调用客户 workflow。
  • 每个新的全局输入动作必须先进入 Guard、manifest approved，再进入真实 workflow 回归。

7. 变量、FB 与数据类型工作流

对象 原子路径 输入 验收
全局变量 菜单定位 → 全局表格 → TSV 粘贴 → 保存 变量定义 TSV 回读名称、类型、值和持久化
FB 自变量 定位 FB → 自变量表 → TSV 粘贴 → 冲突替换 名称、IN/OUT/IN-OUT、类型等 回读方向和类型
FB/程序局部变量 定位 owner program → 局部表格 → TSV 粘贴 局部变量 TSV 回读 owner、名称和类型
数据类型 数据类型树 → 结构体表格 → 增删改操作 结构体成员 TSV/操作 JSON 末尾空行不计成员；System 不修改

自变量表和局部变量表共享焦点状态，Ctrl+Tab 路由必须封装在原子实现中，不应由 Agent 猜测。

8. MNM 与程序体边界

MNM 是模块级导入/导出载体；程序体编辑列表是原位修改接口。两者不能混为同一验收：

MNM import
≠
程序体原位写入
≠
变量/FB 表格写入

程序体原位 workflow 的设计目标是 FB 和每次扫描执行型模块共用同一入口：定位模块、打开程序区、 调用编辑列表插入 MNM 文本。对应 runner：set_fb_program_body_guarded.ps1 和 set_scan_program_body_guarded.ps1。

8.1 关键 Runner 操作流程

import_mnm_guarded.ps1

  1. 预检：读取 MNM 文本，校验 MODULE_TYPE、ExpectedModuleName
  2. 菜单：使用 Guard 调用导入菜单路径
  3. 文件选择：SendKeys/ClipboardPaste + Enter
  4. 验证：assert_kv_module_placement 检查模块类别/位置

set_fb_program_body_guarded.ps1

  1. 找项目树：UIA AutomationId=ProjectTreeView
  2. 打开模块：Select + SetFocus + Enter
  3. 删除旧程序体：^End, Up, ^+Home, Delete
  4. 编辑列表：Ctrl+D 打开编辑列表 modal
  5. 插入程序：ClipboardPaste MNM文本
  6. 错误分支：错误窗 Enter 或编辑列表 Alt+F4

set_fb_arguments_guarded.ps1

  1. 找 FB：ProjectTreeView TreeItem Select/SetFocus
  2. 打开变量编辑：Alt+L
  3. 切换表格：Ctrl+Tab 一次或两次（由当前表状态决定）
  4. 判断分支：Ctrl+A、Ctrl+C 回读当前表；空表跳过清除
  5. 非空清除：Ctrl+A、Shift+Delete；确认弹窗保持前台，Alt+Y 确认
  6. 写入：一次性 ClipboardPaste 完整 ArgumentsTsv；禁止逐行覆盖路线
  7. 快照：解析回读 TSV，写入 fb_snapshot_result.json

compile_and_copy_result_bounded.ps1

  1. 触发编译：F7 或菜单
  2. 等待有界完成：检测编译窗口状态变化
  3. 使用树句柄复制转换结果
  4. 检查 OK/NG：解析复制的文本
  5. 保存文本与 JSON 结果

9. 总结与使用建议

9.1 核心原则

  • 职责分离：Agent 准备输入，Workflow 编排流程，Runner 执行 UI，Guard 保护操作
  • 串行执行：Flat executor 保证 UI 操作串行，避免并发冲突
  • 证据驱动：每次运行产生完整证据链：计划、日志、结果、指纹
  • 契约验收：manifest 定义结果契约，执行器强制验收
  • 失败短路：任一步骤失败立即停止，不继续执行后续 UI 操作

9.2 使用流程

1. 查询能力
→
2. 准备输入
→
3. 调用 workflow
→
4. 验收结果

使用 get_kv_capabilities.ps1 查询可用接口， 准备 TSV/MNM/JSON 输入，以 -STA -NoProfile -ExecutionPolicy Bypass 调用 workflow，检查输出目录中的结果 JSON 和 run.log。

9.3 维护要点

  • 新增 UI 动作必须先加入 Guard 和 manifest approved 列表
  • Runner 变更必须更新 manifest 中的 step_result_contracts
  • 保持 workflow flat，不要嵌套调用客户 workflow
  • UI 原子操作严格小于 10 秒，复杂操作分解为多个步骤
  • 所有桌面操作必须先获取 UI mutex，避免并发冲突
