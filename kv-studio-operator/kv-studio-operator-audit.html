4. Workflow 生命周期

阶段系统动作输出/停止条件
参数预检检查项目、MNM、TSV、JSON 路径和必填参数失败则不启动 UI

串行执行按 plan 顺序调用 runner child，禁止并行 UI 操作任一步失败立即停止后续步骤
结果验收检查结果 JSON、receipt hash、当前运行日志和语义快照不以文件存在代替成功

7. 变量、FB 与数据类型工作流

对象原子路径输入验收
全局变量菜单定位 → 全局表格 → TSV 粘贴 → 保存变量定义 TSV回读名称、类型、值和持久化
FB 自变量定位 FB → 自变量表 → TSV 粘贴 → 冲突替换名称、IN/OUT/IN-OUT、类型等回读方向和类型
FB/程序局部变量定位 owner program → 局部表格 → TSV 粘贴局部变量 TSV回读 owner、名称和类型
数据类型数据类型树 → 结构体表格 → 增删改操作结构体成员 TSV/操作 JSON末尾空行不计成员；System 不修改

自变量表和局部变量表共享焦点状态，Ctrl+Tab 路由必须封装在原子实现中，不应由 Agent 猜测。

8. MNM 与程序体边界

MNM 是模块级导入/导出载体；程序体编辑列表是原位修改接口。两者不能混为同一验收：

MNM import
≠
程序体原位写入
≠
变量/FB 表格写入

程序体原位 workflow 的设计目标是 FB 和每次扫描执行型模块共用同一入口：定位模块、删除旧体、Ctrl+D、粘贴、Tab 一次、插入、关闭弹窗、保存。当前“设计目标”已实现为代码入口，但尚未完成 FB 与扫描模块两条正式真实回归。

9. 错误与停止策略

错误码含义系统行为
KV_UI_WORKFLOW_BUSYKV STUDIO 桌面锁被占用不启动 runner，不发送输入
KV_TARGET_WINDOW_NOT_FOREGROUND目标 HWND 未前台最多一次恢复，失败停止
KV_MODAL_PRESENT存在未处理模态窗转入对话框专用路线或停止
KV_MODULE_LOOKUP_TIMEOUT模块定向查找超过 1 秒停止，不穷举树
KV_FB_ARGUMENT_STEP_FAILEDFB 自变量 runner 失败停止后续步骤，读取同次证据
KV_PROGRAM_BODY_INVALID_MNEMONIC插入非法助记符产生错误窗记录错误文本，错误窗回车，编辑列表 Alt+F4

10. 证据与结果契约

每次正式调用必须使用独立输出目录，至少包含：

计划execution_plan.json
code_fingerprint.json
日志run.log
workflow、锁、步骤、原子动作、错误和结果
步骤证据step_receipt.json
stdout/stderr
截图或快照
结果*_result.json
ok、error_code、输入、语义验收

Receipt hash 只证明证据属于本次运行，不替代变量、模块、程序体或编译结果的语义校验。失败后不能从旧运行目录寻找替代脚本或结果。
