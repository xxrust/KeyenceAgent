# UI 调试：截图优先（铁律）

## 为什么
桌面自动化的失败几乎都不是"代码报错"，而是**界面上有东西挡住了/没点中/字段只读/弹了确认框**。
这些在 exit code 和日志里**看不出来** ✗，只有截图能直接看到 ✓。

## 铁律（必须执行）
1. **出错第一件事 = 截图** ✗不要先看 exit code、不要先看 step 日志
2. 每次关键动作后（点按钮 / 切页 / 开窗 / 保存）都截一张
3. 长流程（>10 秒）→ **全程帧序列**（600 ms/帧），事后按时间轴回看
4. 截图要**自己看**（`read_image`），不要凭日志猜
5. **失败时不要杀 KVS** ✗ —— 一杀现场就没了（弹窗、选中项、提示文字全丢）
6. 判据只认"屏幕上/产物上"的事实 ✓（字段值、窗口是否存在、文件是否被写），**不认 exit code** ✗

## 标准动作
```powershell
# 单帧
powershell -NoProfile -ExecutionPolicy Bypass -File <repo>\scripts\Capture-KvFrame.ps1 -OutDir <dir> -Name step1.png

# 连拍（前台跑主流程，后台每 600ms 一帧）
powershell -NoProfile -ExecutionPolicy Bypass -File <repo>\scripts\Capture-KvFrame.ps1 -OutDir <dir> -Continuous -IntervalMs 600
```
跑完 **一定要 read_image 看**（先看最后一帧，再看失败点附近的帧）。

## 常见"只能靠截图发现"的问题（本项目实测）
| 现象 | 日志看不出 | 截图能看到 |
| --- | --- | --- |
| 点了没反应 | exit=0 ✗ | 弹窗还开着 ✓ |
| 保存没落盘 | "saved" ✗ | 界面还有 `*` 或向导未关 ✓ |
| 字段没生效 | 回读失败 ✗ | 框里还是旧值 ✓ |
| 卡住 | 只是慢 ✗ | 有个模态确认框 ✓ |
| 语义被改坏 | 值对了 ✗ | 坐标单位变成 deg / 模式变成旋转 ✓ |

## 本项目已踩过的坑（务必先查）
1. `执行计算(E)` 只是算 ✓，**必须再点 `OK(W)`** 才应用 ✗
2. `OK(W)` 之后常弹 **「映射设定吗？」→ 点 是(Y)** ✓（可能连续多个）
3. 切换**机械配置**会重置参数、并连带改 `坐标单位/坐标模式/坐标周期` ✗ → 必须先切类型再填值
4. `ValuePattern.SetValue` 对部分字段无效 ✗ → 用 `WM_SETTEXT`（`KvDlgPost::SetText`）✓
5. `轴控制设定` 大表：UIA 读不到 ✗ → **点表格 + Ctrl+A + Ctrl+C** 读剪贴板 ✓
6. 保存：`PostMessage` 的 Ctrl+S **无效** ✗ → 守卫 Ctrl+S ✓
## 铁律补充（2026-10-21）：选择"对象"，不要选"像素位置"
- 表格/列表/树 → 用**控件自身的选区导航**（Ctrl+Home / 方向键 / 首字母）✓，选中后 `Ctrl+C` **读回**验证指向 ✓
- 只有"把焦点交给控件"时才点鼠标 ✓（点控件内部任意位置 ✓）
- 任何"按像素点某个单元格/某一行"的做法 ✗ 都会在分辨率/缩放/字体变化后失效 ✗
