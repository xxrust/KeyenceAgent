# KV STUDIO 弹窗案例（WinForms 批量轴/库对话框、按类型固化）

> 从 `SKILL.md` 抽出（issue #3 R14）。这里只记录**已经实机验证过**的弹窗类型与处理方式；
> 入口与调用方式仍以 `SKILL.md` 的"选择接口 / 调用与验收"为准。
## 批量轴/库对话框（WinForms，不是 #32770）

保存 EtherCAT 配置后依次可能出现（都是顶层 WinForms 窗口，按 `#32770` 扫描会漏）：

1. `EtherCAT设定完成。要批量登录轴吗？` → 是(Y)；
2. `批量登录轴` 表 → OK；
3. `轴的批量登录已经完成。` → 确定；
4. `是否进行新建轴的坐标转换设定？` → 否(N)，可勾选“之后不再启动”；
5. `已导入以下Universal Library。` → 确定。

处理方式：枚举进程所有顶层窗口，按窗口内文本匹配后点击对应按钮；不要依赖固定类名。

## 弹窗类型一经验证必须按类型固化（2026-10-26 教训）

原则：**验证过的弹窗，就把它作为“已知类型”写进该操作的处理表；不要再对同类操作保留通用遍历 + 默认按钮。**

每个已知弹窗必须固化的字段：

- 窗口类名（`#32770` / `WindowsForms10.*` / `Afx*`）；
- 标题原文（注意：模态弹窗标题可能就叫 `KV STUDIO`）；
- 正文关键词（唯一标识该弹窗的文本片段）；
- 按钮文本（`是(Y)`、`OK`、`确定`、`否(N)`…）；
- 出现时机（保存后、导入后、关闭时…）。

实现规则：

1. 该操作只处理自己已知的弹窗集合，逐条精确匹配；命中即点，点完继续等下一个；
2. 遇到未知弹窗 → 立即报错停下，**不要猜按钮、不要默认点 OK**；
3. 排除主窗口只能用 hwnd 或类名（`WindowsForms10.*` 且标题含 ` - [编辑器`），**禁止用 `KV STUDIO*` 之类标题前缀排除**——弹窗标题本身可能就是 `KV STUDIO`，会被一起滤掉（本次 `verified 0/1` 的直接原因）；
4. 每类已知弹窗留一份窗口指纹 fixture（类名/标题/正文/按钮）；修改弹窗处理脚本前后对照跑，确认原来能点的弹窗仍然命中；
5. 新增弹窗类型时只增加该类型的条目，不要扩大通用遍历范围去“顺便兼容”。
