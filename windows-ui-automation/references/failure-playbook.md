# 失败排查手册（按症状）

总原则：**先截图，后读日志**；“哪里不对”通常只有屏幕能回答。

## 0. 通用三步

1. 截图（全屏）+ 保存窗口清单（`Get-UiWindowList`，含 class/title）。
2. 判断“有没有东西挡着/是否前台/目标是否存在”。
3. 只在确认目标后重试；每次重试减少不确定性，不要盲点。

## 1. 点了没反应

| 检查 | 结论 |
| --- | --- |
| 截图里弹窗还开着 | 被模态挡住 → 先处理弹窗 |
| 前台标题不是目标窗口 | 焦点没过去 → `Set-UiForeground` 并校验 |
| 目标控件 `IsEnabled=false` | 条件未满足 → 等状态，不要重点 |
| 目标在 UIA 里不存在 | 自绘/MFC → 换 Win32/坐标 |
| 按钮是 WinForms 且用了 `BM_CLICK` | 不响应 → 聚焦 + 空格 |

## 2. 双击不生效

- 两次点击间隔过大（中间有截图/日志/睡眠）→ 合并成一个原子函数。
- 双击落点在第一下后被选中项改变（列表/树）→ 先单击选中，再单独执行操作。
- 双击被解释为“默认按钮” → 用 Enter/菜单替代。

## 3. 焦点乱跳

- 后台脚本运行时用户动了鼠标/键盘 → 测试期间禁止人工操作。
- `SetForegroundWindow` 被前台锁拒绝 → 校验 `GetForegroundWindow`，失败就报错而不是继续。
- 弹窗属于另一个进程 → 枚举所有进程的 `#32770`，不要只看主进程。

## 4. 字段没生效

- 只读字段：页面上的 Edit 只是显示；必须走“属性/设定”对话框。
- `ValuePattern.SetValue` 无效 → `WM_SETTEXT` 或模拟输入，之后回读。
- 页面有“应用/OK”二级确认 → 改完必须提交，并等保存完成。
- 值被单位/模式联动重置 → 先设模式再设值。

## 5. 表格/网格读不到

- UIA 无单元格：点单元格 → `Ctrl+A` → `Ctrl+C` → 读剪贴板。
- 复制结果只有一列：点击的列决定了复制范围；点左上/行首再全选。
- 复制为空：网格未获得焦点 → 先点内部，再全选。

## 6. 弹窗排队/乱序

- 保存后可能连续出现：保存确认（是/否/取消）→ 刷新确认（确定）→ 业务提示（确定）→ 变量/命名对话框。
- 处理方式：**循环扫描已知弹窗**（标题+文本），处理到“一段时间内没有新弹窗”为止，设总超时。
- 可选弹窗（如变量命名）可直接 `WM_CLOSE`，不让它阻塞主流程。

## 7. 保存看起来成功，其实没有

- 看标题是否还有 `*`。
- 看是否还有“正在应用更改”进度窗。
- 重新打开目标窗口/文件，回读内容。
- 只看日志里的 `saved` 不算。

## 8. 成功是假的

自查：
- 写入后是否**独立回读**？
- 回读是否与写入前**做了差集**（新增了才叫成功）？
- 回读的数据是否来自目标对象，而不是上一次的缓存/剪贴板残留？

没有回读的“成功”一律降级为“未验证”。

## 9. 句柄/元素失效

- `FromHandle` 抛 `ElementNotAvailableException` → 重新枚举，别复用旧句柄。
- 窗口重建（保存、刷新、切换工程）后，所有 hwnd 都可能变。
- 缓存策略：只缓存“进程 id + 标题模式”，每次动作前重查。

## 10. 环境干扰

- 远程桌面断开/锁屏会让截图变黑、输入失效。
- 高 DPI/多屏：坐标必须由 rect 计算，不要写死。
- 输入法/键盘布局会改变 `SendKeys` 的结果（中文输入法开启时尤其明显）。

## 11. 什么时候停

满足任一条件就停并报明确错误码：
- 目标窗口/控件不存在（不是“再等等”）。
- 出现了未知对话框（不是“随便点确定”）。
- 回读与预期不符（不是“再点一次”）。
- 连续两次同样的失败（不是“加大超时”）。
